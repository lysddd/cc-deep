# TodoNow — 产品设计文档

> 日期：2026-06-03 | 状态：待审查

## 1. 产品概述

TodoNow 是一款面向国内用户的**条件驱动的任务+通知系统**。与传统待办应用不同，TodoNow 的核心能力是：用户创建任务并设定触发条件，当条件不满足时，自动向指定接收人发送自定义内容通知。

### 产品定位

| 维度 | 说明 |
|------|------|
| 目标用户 | 国内个人用户 |
| 规模阶段 | MVP 小规模验证（几百到几千用户） |
| 商业模式 | 待定（MVP 先免费，后续探索付费功能） |
| 核心差异 | 条件驱动的通知系统 + 微信端打卡 + 自定义通知内容 |

## 2. 命名 & 品牌

- **产品名**：TodoNow
- **命名原则**：中性、功能导向、不含任何敏感字、商标可查
- **待办事项**：开发前完成商标查询（[中国商标网](http://wcjs.sbj.cnipa.gov.cn/)）、域名注册、微信服务号名称预审

## 3. 核心功能（MVP）

### 3.1 任务条件类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 周期性签到 | 按周期频率打卡，未达标触发通知 | 每天打卡 1 次、每周 3 次 |
| 截止时间未完成 | 在截止时间前需确认完成 | 周五 18:00 前完成周报 |
| 次数达标 | 某周期内达到指定次数 | 每月运动 12 次 |

未来可扩展更多条件类型（通过 JSONB 字段实现，无需改表）。

### 3.2 通知规则

- **通知渠道**（MVP）：邮件（主推，免费），微信模板消息（需服务号认证）
- **通知对象**：自己 或 指定接收人（填邮箱即可，无需对方确认）
- **通知内容**：用户自定义模板，支持变量替换（`{{task_name}}`、`{{deadline}}`、`{{receiver_name}}`、`{{creator_name}}`）
- **免责声明**：每封通知邮件底部标注「此提醒由 xxx 通过 TodoNow 发送，如不想接收请联系发送者」

### 3.3 微信打卡

- 用户关注微信服务号 → 扫码绑定账号（绑定 `wechat_openid`）
- 任务到期时推送模板消息
- 点击模板消息跳转 H5 页面，一键完成打卡
- 打卡来源标记为 `wechat`

### 3.4 用户流程

```
注册（邮箱+验证） → 创建任务（选条件类型+配置参数） →
设置通知（渠道+接收人+自定义模板） → 系统定时检测 →
条件不满足 → 自动发送通知 → 接收人收到提醒
```

### 3.5 页面结构（4 页）

1. **注册/登录** — 邮箱注册 + 邮箱验证
2. **仪表盘** — 活跃任务、今日需签到、近期超时概览
3. **任务管理** — 任务 CRUD + 条件配置 + 通知规则绑定
4. **个人设置** — 通知偏好、绑定微信、注销账号

后期扩展：任务广场、统计数据。

## 4. 数据模型

### 4.1 ER 关系

```
users 1→N tasks 1→N checkin_records
tasks 1→N notifications 1→N notification_logs
```

### 4.2 表结构

**users**（扩展 Supabase `auth.users`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键，关联 auth.users |
| email | text | 邮箱 |
| wechat_openid | text? | 微信绑定标识 |
| display_name | text | 显示名称 |
| email_verified_at | timestamptz | 邮箱验证时间 |
| created_at | timestamptz | 创建时间 |

**tasks**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| user_id | uuid → users | 创建者 |
| title | text | 任务名称 |
| description | text? | 任务描述 |
| task_type | text | checkin / deadline / count |
| condition_config | jsonb | 灵活条件配置（见下方） |
| is_active | boolean | 是否启用 |
| created_at | timestamptz | 创建时间 |

**condition_config 示例**：

```json
// 签到型
{ "type": "checkin", "frequency": "daily", "count_per_period": 1,
  "grace_minutes": 30, "start_date": "2026-06-01" }

// 截止时间型
{ "type": "deadline", "deadline": "2026-06-05T18:00:00+08",
  "require_checkin": true, "remind_before_minutes": [60, 15] }
```

**checkin_records**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| task_id | uuid → tasks | 关联任务 |
| user_id | uuid → users | 打卡用户 |
| checked_at | timestamptz | 打卡时间 |
| source | text | web / wechat |

**notifications**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| task_id | uuid → tasks | 关联任务 |
| channel | text | email / wechat_template |
| recipients | jsonb | 接收人列表 |
| template | jsonb | 自定义通知模板（标题+正文+变量） |
| is_active | boolean | 是否启用 |

**notification_logs**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| notification_id | uuid → notifications | 关联通知配置 |
| task_id | uuid → tasks | 关联任务 |
| recipient | text | 实际接收人 |
| channel | text | 发送渠道 |
| status | text | sent / failed |
| sent_at | timestamptz | 发送时间 |
| error_message | text? | 失败原因 |

## 5. 系统架构

```
┌─────────────────────────────────┐
│       Next.js App Router         │
│    Web 前端 + API Routes         │
│    (国内 Node.js 部署)            │
└──────────┬──────────────────────┘
           │
   ┌───────┼───────┬──────────────┐
   ▼       ▼       ▼              ▼
┌──────┐ ┌──────┐ ┌────────┐ ┌──────────┐
│ Auth │ │  DB  │ │Realtime│ │ pg_cron  │
│邮箱   │ │JSONB │ │仪表盘   │ │定时扫描   │
│注册   │ │条件   │ │实时更新 │ │触发通知   │
└──────┘ └──────┘ └────────┘ └────┬─────┘
   Supabase                        │
                           ┌───────┴──────┐
                           ▼              ▼
                      ┌────────┐    ┌──────────┐
                      │ 邮件服务 │    │ 微信服务号 │
                      │ Resend  │    │ 模板消息   │
                      │ SendGrid│    │ H5 打卡页  │
                      └────────┘    └──────────┘
```

### 技术选型

| 组件 | 选型 | 原因 |
|------|------|------|
| 前端框架 | Next.js (App Router) | 全栈 JS/TS，前端开发者友好 |
| 认证 | Supabase Auth | 开箱即用，邮箱注册+RLS |
| 数据库 | Supabase PostgreSQL | JSONB 灵活字段，Row Level Security |
| 实时更新 | Supabase Realtime | 仪表盘实时刷新 |
| 定时任务 | pg_cron | 每分钟扫描到期任务，无额外运维 |
| 邮件 | Resend / SendGrid | 开发者友好的邮件 API |
| 微信 | 微信服务号 | 模板消息 + OAuth + H5 打卡 |
| 部署 | 国内 Node.js 环境 | ICP 备案必需 |

## 6. 合规设计（「死了么」教训对标）

### 6.1 命名合规
- ✅ 中性名称，无敏感字
- ⏳ 开发前完成商标查询、域名注册、服务号预审

### 6.2 数据隐私
- **P0** 隐私政策 + 用户协议（注册时必须展示）
- **P0** 最小化数据收集（仅邮箱、openid、任务数据）
- **P0** 注销账号（设置页提供，清除全部数据）
- **P0** 通知邮件底部免责声明
- **P1** notification_logs 审计追踪（已内置在数据模型中）

### 6.3 知识产权
- 原创 UI/Logo 设计（使用 Lucide 等开源图标库）
- 第三方依赖统一用 MIT 协议
- 不碰任何已有产品的名称、视觉元素

### 6.4 公司/运营
- MVP 阶段可以个人开发者名义运行
- 付费功能上线前：注册公司/个体户 + ICP 备案
- 确保注册地址可接收工商信函

### 6.5 平台规则
- 不刷榜、不做 ASO 灰色操作
- 遵守微信公众平台运营规范

### 合规优先级总览

| 优先级 | 事项 | 不做的后果 |
|--------|------|-----------|
| 🔴 P0 | 隐私政策 + 用户协议 | 被举报下架 |
| 🔴 P0 | 注销账号功能 | 违反《个人信息保护法》 |
| 🔴 P0 | 通知邮件免责声明 | 被投诉骚扰 |
| 🟡 P1 | ICP 备案 | 网站无法合法上线 |
| 🟡 P1 | 注册公司/个体户 | 无法收费 |
| 🟢 P2 | 微信服务号认证 | 模板消息需要 |
| 🟢 P2 | 商标注册 | 品牌被抢注 |

## 7. MVP 范围

### 包含
- ✅ 邮箱注册 + 登录
- ✅ 三种任务条件（签到/截止/次数）
- ✅ 邮件通知 + 自定义模板
- ✅ 微信服务号绑定 + 模板消息 + H5 打卡
- ✅ 仪表盘（活跃任务概览）
- ✅ 注销账号
- ✅ 隐私政策 + 用户协议

### 不包含
- ❌ 短信通知（后期付费功能）
- ❌ 任务广场（后期）
- ❌ 统计/热力图（后期）
- ❌ 多人协作（后期）
- ❌ 付费/会员系统（MVP 免费）
- ❌ App 端（仅 Web + 微信 H5）

## 8. 关键设计决策

1. **JSONB 存条件配置**：三种条件类型结构各异，JSONB 避免多表 join；后期加新类型不改 schema；应用层用 Zod 校验
2. **pg_cron 而非独立 cron 服务**：MVP 阶段减少运维组件，Supabase 内置即可
3. **接收人无需确认**：降低使用摩擦，通过邮件底部免责声明兜底
4. **Web 管创建，微信管执行**：Web 端负责复杂配置，微信端只做轻量打卡交互
